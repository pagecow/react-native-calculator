# Agent Notify — push setup for React Native Calculator

_Generated by Agent Notify (recipe v1, stack: React Native (bare) — best guess: React Native)._

This pull request adds the Native Notify device-registration client for your
stack. Push delivery (APNs for iOS, FCM for Android) is handled by Native
Notify — you do not run any push infrastructure.

> **Do not commit real credentials.** `NN_APP_ID` and `NN_APP_TOKEN` are read from the app's own configuration at build/run time.

## Steps to finish (the agent cannot do these for you)

1. **Get your app id + app token** from [Native Notify](https://dashboard.nativenotify.com)
   (**Keys** in the project's left sidebar — each value has a Copy button). Put them in
   your app's configuration:
   - The setup pull request puts them where your code reads them (a small config file next to the client). They live inside the app, so keep the repository private (rotate the token on the **Keys** page in [Native Notify](https://dashboard.nativenotify.com) if you ever want a fresh one).
2. **Get the device token** and call the registration function:
   - Install @react-native-firebase/messaging, or read the APNs token natively and pass it through a small native module.
   - Call `registerNativeNotifyDevice({ appId, appToken, platform, apnsToken | fcmToken })` on every token refresh.
3. **Run the app and let it register**:
   - Run it with `npx react-native run-ios` (an iOS Simulator on Xcode 14 or newer, or a real iPhone) and `npx react-native run-android` (an emulator with Google Play services, or a phone).
   - Allow notifications when the app asks.
4. **Send your first push:** click **Send push notification** in the setup guide's first-push card, or just
   ask Agent Notify (API: POST /api/universal/test-send). It is a REAL push
   notification — the banner arrives and it is saved in the notification inbox
   (**Push notifications → Inbox**, where you can delete any you do not want in
   users' inboxes). The transport result is immediate — accepted or failed with
   a plain-English reason.

## Showing pushes on Android

A push to an Android app is an FCM *data* message: Firebase never draws it, the app must. Without code that does, nothing appears while the app is open.

The pull request adds `native-notify/nativeNotifyDisplay.js`: `setUpNativeNotifyDisplay()` creates the notification channel and draws a push in every app state (open, background, closed), with its picture. It does nothing on iPhone.

- `firebase.json` — Firebase's default channel, so a push it draws while the app is closed matches

1. In your terminal, run `npm install @react-native-firebase/app @react-native-firebase/messaging @notifee/react-native`, then `cd ios && pod install` — the Android display needs Notifee.
2. In `index.js`, add `import { setUpNativeNotifyDisplay } from './native-notify/nativeNotifyDisplay';` and call `setUpNativeNotifyDisplay();` before `AppRegistry.registerComponent` — it draws every push on Android.

Until the packages are installed, a check that analyzes every file reports the new file's imports as missing — nothing else is affected, because nothing imports it yet.


## Images in notifications

Fill in **Big picture** when you send from [Native Notify](https://dashboard.nativenotify.com), or set `bigPictureURL` in the API: an `https` JPEG or PNG under 1 MB.

**iPhone:** iOS never downloads a push's image by itself, so this pull request adds a notification service extension to your Xcode project: `NotificationService` (its files are in `ios/NotificationService/`). In Xcode, pick your Team for that target (Signing & Capabilities) unless it already has one, then run the app again.

**Android:** Firebase draws the picture while the app is closed or in the background, and the display module `native-notify/nativeNotifyDisplay.js` draws it while the app is open (see **Showing pushes on Android** above).

The iPhone Simulator never runs notification service extensions, so it shows the text without the picture — test images on an iPhone.

## Before your first push

- **iPhone:** an Apple Developer Program membership ($99 a year — a free Apple ID cannot create the push key) — [enroll](https://developer.apple.com/programs/enroll/); your app's Bundle ID registered with Apple with Push Notifications ticked — [Identifiers](https://developer.apple.com/account/resources/identifiers/list) → + → App IDs → App → Explicit Bundle ID (not a template value like `com.example.…`); the Push Notifications capability on the app target (Xcode → the app target → Signing & Capabilities → + Capability → Push Notifications); then the Apple push key in [Native Notify](https://dashboard.nativenotify.com) (**Setup & docs → Push notifications setup → Connect Apple (iPhone)**).
- **Android:** a Firebase project with your Android app registered under its exact package name, `google-services.json` in the app module (`android/app/`), then the Firebase service-account key in [Native Notify](https://dashboard.nativenotify.com) (**Setup & docs → Push notifications setup → Connect Firebase (Android)**).

## Verify

The agent's verification loop sends a real push through the production
pipeline and reports the exact result. If it fails, the failure code maps to
a fix:

| Result | What it means |
| --- | --- |
| accepted | The device token is valid and credentials work end-to-end. |
| BadDeviceToken | Token is wrong / from the other APNs environment (debug vs release). |
| Unregistered | The app was uninstalled or the token was revoked — register again. |
| InvalidProviderToken | The APNs .p8 / key id / team id in Native Notify settings are wrong. |
| SENDER_ID_MISMATCH | The FCM service account does not match the app's Firebase project. |
